# 演武擂台

《三国：谋定天下》演武大会积分赛的战绩站：一个 Node 进程 + 一个 SQLite 文件 + 一个图片文件夹。
不用 Docker、不用对象存储，也没有前端构建步骤。

按 `演武攻略指南.md`（开发文档 v2.1）实现。业务规则编号（R1–R12）与文档一致。

## 快速开始

```bash
cd /home/raving/work/sanmouyanwu
npm install                 # 已完成
cp .env.example .env        # 不需要，.env 已生成
```

浏览器打开 `http://<宿主机IP>:3000`，用管理员登录 → 管理页生成邀请码 → 把注册链接发给朋友。

- **Node.js 20.6+**（用到 `--env-file`）。本机实测 v20.20.2 ✓
- 首次 `npm install` 会编译 better-sqlite3（原生模块）
- 还需要 **sharp**（上传时压图，见「图片压缩」）。它的平台二进制
  （`@img/sharp-linux-x64`）走 npm registry，**不碰 GitHub**，所以这台机器上装得动——
  这点和 better-sqlite3 不一样，不需要 `npm_config_build_from_source`。

> ⚠️ **本机装依赖时的坑**：这台机器 GitHub 域名 DNS 不可解析，better-sqlite3 的预编译包
> 下载通道（GitHub Releases）不可用。已用下面的方式从源码编译成功，换机器重装时照抄：
>
> ```bash
> npm_config_build_from_source=true npm install
> ```
>
> npm registry 与 nodejs.org 走 IPv6 可达，node-gyp 能正常拿头文件。

### .env

```ini
SESSION_SECRET=<64 位随机串，已生成，权限 600>
PORT=3000
MAX_LINEUP=6        # 每人每期阵容截图上限
```

那样绕过 nginx 直连 `:3000` 也能登录，等于把限流和反代都架空了。

## 常驻运行

应用本身只是 `node --env-file=.env app.js`。进程守护三选一：

> 📌 本仓库**不含 `deploy/` 目录** —— 里面的 nginx 配置、systemd 单元、`DEPLOY.md`
> 都是照着部署那台机器写的（含本机路径和域名），没有一起公开。下面 B 节和
> 「反代（nginx）」里提到的现成文件，照着自己机器改一份即可。

**A. pm2（文档推荐，尚未安装）**

```bash
npm i -g pm2                    # 需要联网装全局包，装之前先确认
pm2 start app.js --name yanwu --node-args='--env-file=.env'
pm2 save && pm2 startup         # 开机自启
pm2 logs yanwu
```

**B. systemd（推荐，不用装全局包）**

现成单元文件在 **`deploy/yanwu.service`**：

```bash
sudo cp deploy/yanwu.service /etc/systemd/system/yanwu.service
sudo systemctl daemon-reload && sudo systemctl enable --now yanwu
systemctl status yanwu          # 看是否 active (running)
journalctl -u yanwu -f          # 看日志
```

单元里带了 `ProtectHome=read-only` + `ReadWritePaths` 等加固。万一启动失败，
**先注释掉最后那几行加固再试**——那是唯一可能拦住的配置，其余都是常规项。

**C. 前台手动跑**：`npm start`（关掉终端就停）。

### 端口

`.env` 的 `PORT=3000`，本机 3000 空闲。注意本机 `0.0.0.0:8080` 已被别的服务占用，
别把 `PORT` 改成 8080。

### 反代（nginx）

现成配置在 **`deploy/nginx-yanwu.conf`**，拷到 `/etc/nginx/sites-available/yanwu` 即可。
完整步骤见 `deploy/DEPLOY.md`。

两个容易踩的点，配置里都处理了：

- **`client_max_body_size 64m`**：一次最多传 6 张图、**单张原图**上限 10MB，单个请求能到 60MB，
  设小了批量上传会被 nginx 用 413 打回。别照抄网上常见的 `1m`。
  注意 10MB 是**收下来时的**限制；存进 `uploads/` 的是压缩后的图，每张 <1MB（见「图片压缩」）。
- **真实 IP 透传**：`limiter.js` 按 `req.ip` 记登录失败次数。IP 没还原的话，
  经 frp 进来的请求在 Node 眼里全是 `127.0.0.1`，任何人输错 10 次密码就会把**全站**锁 15 分钟。
  配置里用 `set_real_ip_from 127.0.0.1` + `real_ip_header X-Forwarded-For` 还原。

`/uploads` **必须走 Node**（截图挂在登录鉴权后面），只有 `/public` 交给 nginx 直接发。

## 图片压缩

玩家传上来的图**一律重编码成 jpg，压到 1MB 以下**才入库（`upload.js` 的 `compressUploads`）。
手机直接拍的截图动辄 5–10MB，走 frp 那点带宽传一张要等半天。

流水线是 `multer` 先把原始文件收进 `uploads/.incoming/`，紧接着 `compressUploads`
把每张压成 `<uuid>.jpg` 落到 `uploads/`，然后**无论成败都删掉暂存文件**，
并把 `file.filename` 换成压缩后的名字——所以路由层一行都不用改。
（`.incoming` 以点开头，`express.static` 默认不 serve 点开头的路径，不会被 `/uploads` 暴露。）

压缩阶梯在 `upload.js` 的 `LADDER` 里，**第一档特意不缩尺寸**，只重编码：

| 输入 | 输出 | 尺寸 |
|---|---|---|
| 2844×1280 游戏截图，1.16MB | **319KB** | 不变（2844×1280） |
| 1238×619 PNG，0.97MB | **133KB** | 不变，并转成 jpg |
| 4000×3000 噪点照片，11.6MB | **934KB** | 降到 1920×1440 |

游戏截图这种大片纯色的图，只重编码就够了，没必要动人家的像素；真正压不动的
（大面积噪点的照片）才逐档降长边和画质，直到进 1MB。实测数据在上面，改阶梯时照着验。

顺带解决的两件事：

- **EXIF 方向**：`.rotate()` 会把手机竖拍的照片摆正。以前不管这个，竖着拍的图在网页上是躺着的。
- **PNG 的透明区**：jpeg 不支持透明，会变黑。先 `flatten` 到白底再编码。

### 拖拽上传

`/lineup`（阵容截图）和 `/score`（积分截图）两个页面的文件框都能**直接拖文件进去**。
`public/upload.js`，原生 JS，没有构建步骤。

做法是把拖进来的文件**灌进那个原生 `<input type="file">`**
（`input.files = dataTransfer.files`），表单照原样提交 —— 路由层、multer、
压图流水线一行都没改，服务端根本不知道有拖拽这回事。

所以它是**增强**，不是依赖。三种情况下页面退回原来的样子，点 input 选文件一切照旧：

- **JS 关了 / 脚本没加载**：虚线框、提示、结果一行都不会出现（那些 DOM 全由 JS 生成，
  模板里没有）。不在没有 JS 的页面上留一句「可以拖进来」的空头支票。
- **浏览器太老**：Safari < 14.1、Firefox < 62 不给 `input.files` 赋值，脚本开头探一下，
  赋不进去就整段不启用。
- **触摸为主的设备**（手机、平板）：`(hover: none) and (pointer: coarse)` 时整段跳过 ——
  那边本来就是点一下从相册选，摆个拖不动的框纯属添乱。

拖进来之后客户端会先筛两道，都只是为了少让人白等一次上传（**服务端仍是最终裁判**，
`upload.js` 的 multer 配置一个字没改）：

| 情况 | 表现 |
|---|---|
| 非 jpg / png / webp | 挡在外面，并说明忽略了哪个文件（判据和 multer 的 `EXT` 表一致） |
| 一次拖的比剩下的额度多 | 截到剩余额度，说明「多出来的 N 张没收」（额度来自模板的 `data-max`） |
| 额度已满（`data-max="0"`） | 直接说「已经传满了，先删掉几张再拖」，一个字节都不传 |
| 拖的是选中的文字 / 页面链接 | 不算数：不亮框、不动 input |
| 拖到虚线框**外面** | 拦住浏览器打开该文件的默认行为（否则整页跳走），提示往框里拖 |

结果（选了几张、多大、忽略了什么）显示在框里一行提示上，带 `aria-live` 让读屏软件也念一句。

三个浏览器上的坑，改的时候别踩：

- **`dragover` 必须 `preventDefault()`**。不拦的话浏览器判定这个位置「不接受放置」，
  `drop` 事件根本不会来，松手时反而按默认行为去打开那个文件。
- **灌文件之后原生控件自己会更新**（显示「2 files selected」），所以提交时表单是真带着
  这些文件的 —— 这一点在无头 Firefox 里逐条验过，见「自测清单」。
- **虚线框不能「淡入」**。`.drop-field` 上有 `border-color` / `background-color` 的过渡
  （拖进来时描边转金要用它），而加类的瞬间浏览器会从「没有框」过渡到「有框」，
  页面一打开就能看见框淡入 140ms。所以 `upload.js` 加类前先把 `transition` 压成 `none`、
  逼一次重排让它落地，再加类。**调试这个的时候很容易被自己骗**：截图若正好落在过渡中间，
  读到的 computed style 是过渡的**起始值**（描边是 `currentColor`、底色透明），
  连 `!important` 都「不生效」—— 那不是层叠问题，是过渡还没跑完。

`upload.js` 和样式表一样带 `?v=<文件 mtime>`（见 `app.js` 的 `assetVer`）：
nginx 给 `/public/` 盖了 `max-age=604800`，不带版本号的话改完这个脚本，
浏览器一周都不会来取新的 —— 那段时间里用户看到的是「拖了没反应」。

### 显示尺寸

上传的截图在两个地方展示，**都是 200×160、`object-fit: contain`**：

| 位置 | 选择器 | 桌面 | 手机（≤640px） |
|---|---|---|---|
| 首页 · 本期排名表 | `.thumb` | 200×160 | 120×96 |
| 首页 · 本期阵容墙 | `.shot-frame img` | 200×160 | 150×120 |

用 contain 不用 cover，是因为阵容截图是 2.2:1 的超宽图，cover 会左右各裁掉约 1/4，
而武将恰恰铺在两侧 —— 裁掉就正好看不见了。**这是有意的，别"顺手优化"成 cover。**
留白用卡片底色 (`--yw-ink-1000`)，看起来是刻意的暗底 letterbox，不是图没加载出来。

代价是 2.2:1 的图在 200×160 的框里实际只占 200×90，上下各留一截。
**看图的人得点图开原图才看得清阵容**，这是 contain 换来的诚实。

> 这两处之外的 `/seasons/:id`（`.entry-shots`，260×200）和 `/lineup`（`.gallery`，150px 高）
> 尺寸另算，没跟着改 —— 它们本来就不大。

### 阵容说明（首页阵容墙）

首页阵容墙每张卡片，除了那个人的第一张阵容截图，下面还展示他自己的**阵容说明**
（`entries.lineup_note`，`/lineup` 页填的那个）。

卡片只有 200px 宽，而说明最长 1000 字，全摊出来会把整行卡片一起顶高（grid 每行等高，
最高的那张说了算），所以用 `-webkit-line-clamp: 5` 截到 **5 行**，超出打省略号。
没填说明的人不渲染这一块，不会留个空盒子。

两个实现上的坑，改的时候别踩：

- **只能用 `margin` 排版，不能用上下 `padding`**。Firefox（实测 140.13esr）的
  `-webkit-line-clamp` 算盒子高度时不计 padding，给了上下 padding 就会在第 5 行底下
  漏出第 6 行的一条边。所以 `.shot-note` 是 `padding: 0` + 四周全交给 margin。
- **`white-space: pre-wrap` 是故意的**，为了保住玩家自己敲的换行。「一队……／二队……」
  这种分行写的说明压成一大坨就没法看了。

截断这件事是有代价的：**完整说明目前只有 `/seasons/:id` 赛期详情页能看到，而那里只列出
交过积分的人**。传了阵容却没交积分的人，他的完整说明没有任何页面能看到 —— 这是实现
文档里没覆盖到的口子，要么给详情页的「还没交积分」名单也挂上说明，要么以后再说。

### 给老图补压

压图功能上线**之前**传进 `uploads/` 的图不会自动变小，得手动补一遍：

```bash
npm run recompress              # 预演：只报告会做什么，一个字节都不动
npm run backup                  # 真改之前先备份——原图会被替换掉，不可逆
npm run recompress -- --apply   # 真改
```

只处理**数据库里被引用着**的图，没人引用的孤儿文件只报告不删。
`.png` 那张会被转成 `.jpg` 并把数据库里的引用一起改掉（同一个事务），
所以 `entries.score_image` / `lineup_images.filename` 不会指空。
压完的图下次再跑就是「已达标，跳过」，可以反复执行。

它走的是 `upload.js` 里**同一套** `compressOne` 阶梯，不是抄一份——
以后改阶梯，两边不会改岔。

## 打分（成员互评）

站里有**两种数字**，别搞混：

| | 积分（`entries.score`） | 打分（`ratings.value`） |
|---|---|---|
| 谁给的 | 玩家自己上传截图 | 其他成员点一下 |
| 值域 | 0–999999999 任意整数 | 固定五档 `50 / 200 / 250 / 300 / 400` |
| 影响名次 | **是**，积分最高者获胜 | **否**，只展示 |
| 影响阵容墙顺序 | 否 | **是**，均分高的排在前面（2026-10-13 起） |

打分**不进** `/rank`、不进结算、不影响名次 —— 名次永远只看积分。
它只决定**首页阵容墙的展示顺序**：均分高的排前面，没人打分的垫底（见「取舍」表）。

### 怎么投

首页阵容墙每张卡底部五个档位按钮，点一下就投出去。**一个 `<form>` 五个
`<button name="value" value="400">`**，没有 JS —— 和站里其它写操作一样是纯表单 POST。
投完跳回 `/#e<entry.id>`，落在那张卡上而不是页顶（阵容墙在排名表下面，
跳页顶会让人以为没生效）。卡上当场变成「你打了 400」。

### 三条硬规矩

1. **一期内一个阵容只能投一次，打完不能改。** 靠 `UNIQUE (entry_id, rater_id)`
   保证，不是靠前端把按钮藏起来；路由里再挡一道。所以**没有「改分」入口** ——
   卡上直接写「一期内不能改」，省得人去找一个不存在的按钮。
2. **只能投给已经传了阵容的人**（阵容墙上出现的才有按钮；直接 POST 一个没传图的
   `entry` 也会被拒）。
3. **只能投进行中的期。** 期一结算，卡片上就不再出按钮，直接 POST 也会被拒。
   首页在没有进行中的期时会回退显示上一期的结果，那时墙上的分照常展示，只是不能投。

**可以给自己打分**（没做限制，一视同仁）。

### 五档从哪来

唯一真源是 `db.js` 的 `RATE_VALUES` —— 路由的校验、模板里的按钮都读它，
**改档位只改这一处**。

`schema.sql` 里**故意没给 `value` 加 CHECK**：档位是产品参数，多半还会调整，
而 SQLite 改 CHECK 要整表重建；上面 `entries` 的 R4 CHECK 守的是不变量
（分数/截图/时间三个字段同生共死），性质不同。唯一写入口是 `/entries/:id/rate`
这一个路由，校验就够。

### 均分 / 最高 / 最低怎么算

一期里所有打分**一次查回来**（`db.getSeasonRatings`），在 JS 里按 `entry_id` 归并
（`db.summarizeRatings`）—— 打分是「人数 × 阵容数」，量级很小，不值得写一堆
`GROUP BY` 再逐个回查打分人。

- **均分**保留 1 位小数（`233.3`）；正好是整数时 JS 直接打印成 `250`，不会出现 `250.0`。
- **最高/最低把并列的人全列出来**，再截前两个、后面收成「等 N 人」
  （`app.js` 的 `nameList`）。只有五档，并列太常见了 —— 只挑一个人显示是误导。
- 打分人是纯文本，不做链接：卡片上已经有「昵称」和「图」两个链接了。

汇总的 `viewerId` 一路传进 `db.getLineupWall(seasonId, viewerId)`，用来认出
「我投的是哪一档」。

### 只显示在首页阵容墙

`/seasons/:id` 没动。所以**新一期开始后，上一期的阵容墙就从首页消失了**，
那些均分要在「我的打分记录」里才翻得到。

### 点错了怎么办

打分不能改，所以留了个管理出口：`/admin` 的**「打分记录」**（默认用 `<details>`
收起），列出**进行中那一期的全部打分**，每条一个【清除】。清掉之后那个阵容对
这个人重新变成「没打过」，可以再投一次。

只列进行中的期就够：打分只能在进行中的期产生，**要清历史期的先【撤销结算】**，
那一期就成了进行中的期，记录自然出现在这儿。

### 样式上的两个坑（都是实测出来的）

1. **`.rate-k` 不能用 flex 的定宽基准。** 一开始写的 `flex: 0 0 2em`，
   而 2 个汉字在 0.72rem 下正好等于 2em —— 差一点点就折成「均」/「分」两行。
   改成 `flex: 0 0 auto` 交给 max-content：三个标签都是 2 个字，宽度自然一样，
   数字照样对齐。
2. **打分人那一串用 `white-space: nowrap`，配 `.rate-line { flex-wrap: wrap }`。**
   否则 `overflow-wrap: anywhere` 会把「张三、李四」从中间劈成
   「张三、李」/「四」。nowrap 之后它作为一个整体换行：装得下就留在同一行，
   装不下就整段下移一行。

另外注意 **Pico v2 的根字号是响应式的**：≥1280px 时 `1rem = 20px`（125%），
窄屏才是 16px。同一个 `0.7rem` 在桌面和手机上差 25%，量尺寸时别忘了。

## 备份与恢复

```bash
npm run backup          # 保留最近 30 份
KEEP=90 npm run backup  # 保留最近 90 份
```

备份落在 `backup/`，每份两个文件：`app-<时间戳>.db`（`VACUUM INTO` 做的一致性快照，
不用停服务）和 `uploads-<时间戳>.tar.gz`。时间戳是上海时区的 `YYYYMMDD-HHMMSS`。

挂到 crontab 每天凌晨 3 点（宿主机时区是 America/New_York，注意换算）：

```cron
0 3 * * * cd /home/raving/work/sanmouyanwu && /usr/bin/npm run backup >> backup/backup.log 2>&1
```

**恢复**：停掉服务 → 把 `app-<ts>.db` 覆盖成 `data/app.db`（同时删掉 `data/app.db-wal`、`data/app.db-shm`）
→ `tar xzf uploads-<ts>.tar.gz -C /home/raving/work/sanmouyanwu` → 起服务。

## 自测清单

已用一次性实例跑过 48 项端到端断言；后来为拖拽上传（54 项）、打分（75 项）
各跑过一次专项回归，全部通过。手工复验时按下面的清单走：

**账号**
- [ ] 邀请码错误 → 提示"邀请码不正确或已失效"
- [ ] ID 大写自动转小写；`AB`（太短）、`zhaoyun`（重复）都被拒
- [ ] 两次密码不一致、密码不足 6 位都被拒
- [ ] 管理页点【关闭注册】后，再用邀请码注册 → "注册暂未开放"
- [ ] 禁用某成员后：他登录被拒；已登录的刷新页面即被踢出；**历史战绩仍能打开**；不再出现在"还没交积分"名单里
- [ ] 连错 10 次密码 → 锁 15 分钟

**图片**
- [ ] 传一张 5MB 的手机截图 → 上传成功；`ls -l uploads/` 里那张 **<1MB**，且网页上不是躺着的
- [ ] 传一张 2.2:1 的超宽阵容图 → 缩略图**左右两侧的武将都在**（没被裁掉），点开看原图也正常
- [ ] 阵容说明填个上百字带换行的 → 首页阵容墙上那张卡显示 **5 行后打省略号**，
      下面**不漏出第 6 行的半截字**（Firefox 下最容易出这个毛病，见「阵容说明」一节）
- [ ] 把图直接拖进虚线框 → 原生控件上出现文件名，提交后图片正常入库；
      拖一个 `.txt` 进去 → 被挡下并说明忽略了它；拖到框**外面** → 页面不会跳走
- [ ] 关掉 JS（或浏览器设置里禁用）再进 `/lineup`、`/score` → **没有**虚线框、
      也**没有**「也可以把图片拖进来」那句提示，点 input 选文件照常能传

**比赛**
- [ ] 没传截图就交积分 → 被拒（R4）
- [ ] 只传阵容不交积分 → 不算参赛，不进排行榜、不计胜率（R5）
- [ ] 两人同分 → **先提交的排前面**（R2）
- [ ] 本人改分或换截图 → 提交时间刷新；只改阵容说明 → 时间不动；分数截图都没变再提交一次 → 时间不动
- [ ] 管理员修正积分 → 分数变了，**提交时间不动**
- [ ] 撤回积分 → 回到"没打"状态（阵容截图还在）
- [ ] 只有 1 人交积分时点【结束本期】→ 提示少于 2 人不能结算
- [ ] 结算后：看板/历史/排行/个人页数字一致；撤销结算后可以继续改分，再结算结果正确
- [ ] 删除赛期 → 数据库记录和 `uploads/` 里的图片一起没了

**权限**
- [ ] 未登录访问任何页面 → 跳登录；`/uploads/xxx.jpg` 未登录也拿不到（R3）
- [ ] 普通成员访问 `/admin` → 403
- [ ] 成员 A 删不掉成员 B 的阵容图

**打分**
- [ ] 首页阵容墙每张卡底部五个档位 → 点一下立刻投出去，页面**落回那张卡**（地址栏带 `#e<id>`），
      卡上变成金色的「你打了 X」，按钮消失
- [ ] 同一张卡再点另一档 → 提示"一期内只能打一次"，**库里还是原来那一档**
- [ ] 手动 POST 一个非档位的值（`100`、`abc`、空）→ 被拒，库里没多记录
- [ ] 已结算的期：首页墙上**一个按钮都没有**，均分照常显示；手动 POST → 被拒
- [ ] 三人给同一套阵容打 400/250/50 → 均分 **233.3**，最高 400、最低 50 后面各跟打分人
- [ ] 两票并列最高 → **两个名字都列出来**；三票以上 → 「等 3 人」，不铺开
- [ ] `/ratings`（导航「打分」）只列**我自己**投过的，换个账号看不到我的；一条没有时是空态
- [ ] 管理员在 `/admin` 的「打分记录」里【清除】一条 → 那个人**可以重新投**
- [ ] 删掉整个赛期 → 打分记录跟着 `entries` 一起级联没了
- [ ] 打分**不影响** `/rank`、不影响结算，但**决定首页阵容墙的顺序**（均分降序，没打分的垫底）

## 目录

```
app.js            入口：中间件、路由挂载、统一错误处理
db.js             连接、建表、全部 SQL（含结算事务）
schema.sql        建表语句
upload.js         multer 配置、上传后压图、删文件工具
limiter.js        登录/注册失败限流（内存，重启清零）
routes/auth.js    注册、登录、登出、改密码
routes/main.js    看板、阵容、积分、打分、历史、排行、个人页
routes/admin.js   赛期、邀请码、成员、修正积分
views/            EJS 模板（服务端渲染，全部表单提交）
public/           pico.min.css（v2.1.1，本地）+ style.css + upload.js（拖拽上传）
scripts/          create-admin.js、backup.js、recompress.js
deploy/           本机专属，未纳入本仓库（nginx 配置、systemd 单元、DEPLOY.md）
data/app.db       自动生成
uploads/          所有图片
backup/           备份
```

所有路径都用 `__dirname` 拼接，从哪个目录启动都能跑。

## 关于开发文档 v2.1

文档在 **第 549 行被截断**（断在 `routes/auth.js` 的注册校验中间），
第 9.6 节之后和第 10–13 章不在文件里。已实现的部分与文档逐条对齐，
下面是需要自己定的地方，以及为什么这么定：

| 项目 | 处理 | 原因 |
|---|---|---|
| 阵容截图上限 | `MAX_LINEUP`，**按"每人每期总数"**限制 | 路由表写"最多 6 张"，错误处理写"一次最多传 6 张"。两个都满足：单次传 7 张被拒，累计超 6 张也提醒先删 |
| 提交时间刷新 | 分数**或**截图任一变化才刷新 | 按文档字面实现。都没变就不动时间，避免重复提交无谓地把同分排名往后挤 |
| 管理员修正积分 | 仅限进行中的期，且该成员必须**已交过积分** | DB 的 CHECK 约束要求分数/截图/时间三者同生共死，所以不能凭管理员一己之力给没截图的人补分 |
| 撤销结算 | 若已有别的进行中赛期 → 拒绝并提示 | `one_open_season` 唯一索引保证同时只有一个 open 期，硬来会违反约束 |
| 图片上传失败 | 返回纯文本错误页 | 按文档的统一错误处理实现，不回显表单（图片不会丢，已上传的会删掉） |
| multer 版本 | 仍是文档指定的 `^1.4.5-lts.1` | 但装的时候 npm 会警告 1.x 有已知漏洞、已 deprecated。要升级只需把 `package.json` 改成 `^2.0.0`（`single`/`array` API 兼容），代码不用动 |
| 看板的阵容墙取谁 | 本期**所有传了阵容的人**，不限交过积分的（`db.getLineupWall`） | 取 `ranking` 的话，新一期刚开、有人传了图但还没人交积分时，墙会是空的。没交分的右侧标"未交积分"，不给名次 |
| 阵容墙的排序 | **互评均分降序**（没人打分的垫底），不是积分序（2026-10-13 改） | 积分名次是上面那张排名表的活儿；墙这边大家想看的是"哪套阵容公认最好"。均分相同的保持积分序（`sort` 稳定），不另立同分规则。`rank` 仍按积分序算，所以卡上的 `#N` 是**积分名次**、和排名表对得上，只是不再等于"墙上第几张" |
| 阵容墙的图片尺寸 | 每张 **200×160**，`object-fit: contain`（2026-10-13 从「宽 ≤600px」改小） | 阵容截图实测 2844×1280（约 2.2:1）。`cover` 会左右各裁掉约 1/4，而武将恰恰铺在两侧 —— 那正是要看的东西，所以**宁可留边也不裁**。代价是 2.2:1 的图在 200×160 框里实际只占 200×90，上下留边；要看细节点图开原图 |
| 阵容墙的说明 | 卡片里除了第一张图，还展示该成员的阵容说明，`-webkit-line-clamp: 5` 截到 5 行（2026-10-13 加） | 卡片只有 200px 宽，说明最长 1000 字，不截断会把整行卡片顶高。详见「阵容说明（首页阵容墙）」一节，那里记了两个必须照做的实现细节（只准用 margin；`pre-wrap` 是故意的） |
| 列表缩略图 | 200×160，`object-fit: contain`；`.thumb-row` 封顶 420px | 见「图片压缩」一节。封 420px 是为了不让 6 张 200px 宽的图把表格的 max-content 撑到 1200px——那会超出 `.container` 变成横向滚动。420px 刚好一行两张，整表约 1100px，1280 视口下装得下 |
| 阵容墙的列数 | `repeat(auto-fill, 200px)`，左对齐，1280 视口下排 5 张；窄屏降到 150px | 轨道**写死 200px**，不用 `minmax(200px,1fr)`——后者会把列拉伸填满整行，卡片就不是 200 宽了。左对齐是因为上面的 `h3` 和说明都左对齐，卡片居中会和大标题错开 |
| 样式表的缓存 | 模板里给两个 CSS 带上 `?v=<文件 mtime>`（`app.js` 的 `assetVer`，`upload.js` 同） | nginx 对 `/public/` 有 `expires 7d`，不带版本号的话改完 CSS 浏览器最多一周都不来取新的，只能让用户按 `Ctrl+Shift+R`。带 mtime 后每次改动都是新 URL，刷新即生效。**这只解决样式表**，`/uploads` 下的图片名本来就是随机 UUID，天然不会撞缓存 |
| 拖拽上传 | `public/upload.js`，拖进来的文件灌进原生 `<input type="file">`，表单和路由一行不改（2026-10-13 加） | 同样是 `?v=<mtime>` 破缓存——脚本比样式表更经不起缓存，改了不生效就是「拖了没反应」。没有 JS / 老浏览器 / 触摸设备三种情况下整段不启用，页面退回原样，详见「拖拽上传」一节 |
| 打分（成员互评） | 五档固定 `50/200/250/300/400`；**一期内一票、打过不能改、可以给自己打**；均分/最高/最低**只在首页阵容墙**显示（2026-10-13 加） | 这三条都是你定的。因为「不能改」，另外补了管理员在 `/admin` 清除的出口（否则点错没救）。打分不进排名、不影响结算——名次仍然只看积分。详见「打分」一节 |
| `ratings.value` 不加 CHECK | 值域只由 `db.js` 的 `RATE_VALUES` 管 | 档位是产品参数、多半还会调，而 SQLite 改 CHECK 要整表重建；`entries` 的 R4 CHECK 守的是不变量，性质不同。唯一写入口是一个路由，校验够用 |
| 打分人只列前两个 | 并列的最高/最低分，名字截前两个、后面收成「等 N 人」（`app.js` 的 `nameList`） | 只有五档，并列太常见；卡片只有 200px 宽，把七八个名字全摊出来会把整行卡片顶高。只挑一个显示又是误导 |

`.env` 里的 `SESSION_SECRET` 是随机生成的，权限 600，已在 `.gitignore` 里。
